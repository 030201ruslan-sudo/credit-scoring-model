# Credit Scoring Model

## Описание проекта

Итоговый проект по дисциплине "Автоматизация процессов разработки и тестирования моделей машинного обучения".

Цель проекта - создать автоматизированную систему для прогнозирования вероятности дефолта клиента по кредитной карте.

Для работы используется датасет **Default of Credit Card Clients** из UCI Machine Learning Repository.

## Основные этапы

1. Загрузка и подготовка данных.
2. Исследовательский анализ данных (EDA).
3. Проверка качества данных.
4. Обучение и настройка модели машинного обучения.
5. Отслеживание экспериментов с MLflow.
6. Контроль версий данных и моделей с DVC.
7. Автоматическое тестирование с pytest и GitHub Actions.
8. Создание API с FastAPI и запуск через Docker.
9. Мониторинг изменений распределения данных.

## Структура проекта

- `data/` - исходные и обработанные данные.
- `models/` - сохранённые модели.
- `notebooks/` - исследование данных.
- `src/data/` - подготовка и проверка данных.
- `src/features/` - создание новых признаков.
- `src/models/` - обучение моделей и предсказания.
- `src/api/` - API для получения предсказаний.
- `tests/` - автоматические тесты.


## Установка и запуск

### 1. Установка зависимостей

Создать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установить библиотеки:

```bash
pip install -r requirements.txt
```

### 2. Подготовка данных и модели

Исходный датасет и обученная модель хранятся
в Google Drive под управлением DVC.

После установки зависимостей выполните:

```bash
dvc pull
```

Команда загружает необходимые файлы:

- `data/raw/UCI_Credit_Card.csv`
- `models/credit_model.pkl`

Для доступа к Google Drive необходимо пройти
авторизацию Google и иметь права на папку DVC.

Если файлы уже загружены, DVC сообщит:

`Everything is up to date.`

### 3. Проверка данных

```bash
python -m src.data.validation
```

### 4. Обучение модели

```bash
python -m src.models.train
```

Модель обучается методом Logistic Regression.
Для выбора параметра регуляризации используется GridSearchCV.
Результаты эксперимента сохраняются в MLflow.

### Просмотр экспериментов MLflow

После обучения модели результаты сохраняются
в локальной базе данных `mlflow.db`.

Для просмотра экспериментов выполните:

```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
```

Откройте в браузере:

http://127.0.0.1:5000

Выберите эксперимент `Credit_Default_Prediction`.

В MLflow сохраняются:
- Параметры модели: `C`, `cv`.
- Метрики: ROC-AUC, Precision, Recall, F1-score.
- ROC-кривая.
- Обученная модель `credit_default_model`.

Файл `mlflow.db` не включён в GitHub.
Для создания нового эксперимента необходимо
повторно запустить обучение модели.


### Автоматизация через DVC

Подготовка данных и обучение модели объединены в DVC-пайплайн.

Для запуска выполните:

```bash
dvc repro
```

Пайплайн состоит из двух этапов:

- `prepare` - разделение исходного датасета на train.csv и test.csv.
- `train` - обучение модели и сохранение credit_model.pkl.

Конфигурация находится в `dvc.yaml`.
Файл `dvc.lock` фиксирует версии данных и модели.

Если данные и код не изменились, DVC пропускает повторное выполнение стадий.

Для загрузки результатов в Google Drive:

```bash
dvc push
```

### Имитация новых клиентов

Запустите FastAPI:

```bash
python -m uvicorn src.api.main:app --port 8000
```

Во втором терминале выполните:

```bash
python -m src.monitoring.simulate
```

Скрипт отправляет 10 запросов в API и выводит прогнозы.

### Мониторинг Data Drift

```bash
python -m src.monitoring.drift
```

Мониторинг рассчитывает KS statistic, p-value и PSI
для пяти признаков.

Результаты сохраняются в
`data/processed/drift_report.csv`.

Проверка использует две части исходного датасета
и демонстрирует принцип обнаружения Data Drift.

### 5. Запуск автоматических тестов

```bash
python -m pytest tests/ -v
```

Тесты проверяют валидацию данных, работу API
и статистический тест для обнаружения Data Drift.

### 6. Запуск API

```bash
uvicorn src.api.main:app --reload
```

Документация API доступна по адресу:

http://127.0.0.1:8000/docs

### 7. Запуск через Docker

Собрать образ:

```bash
docker build -t credit-scoring-api .
```

Запустить контейнер из корневой папки проекта:

```bash
docker run --rm -p 8000:8000 -v "$(pwd)/models:/app/models:ro" credit-scoring-api
```

Для работы метода `/predict` файл `models/credit_model.pkl`
должен находиться на компьютере, где запускается Docker.

### 8. Мониторинг Data Drift

```bash
python -m src.monitoring.drift
```

Программа сравнивает распределения пяти признаков
в двух частях исходного датасета.

Результаты сохраняются в файл:

`data/processed/drift_report.csv`

Это демонстрационная проверка, а не мониторинг
реального потока новых данных.

## Результаты модели

Используется Logistic Regression с предварительной
обработкой признаков.

На тестовой выборке получены следующие результаты:

- ROC-AUC: 0.7413
- Precision: 0.6552
- Recall: 0.2864
- F1-score: 0.3985

Разделение данных: 80% на обучение и 20% на тестирование.
Используется `random_state=42`.

## Автоматизация

В проекте настроен GitHub Actions.

При отправке изменений в ветку `main`
автоматически устанавливаются зависимости
и запускаются тесты pytest.

Тест API использует подмену модели,
поэтому для его выполнения на GitHub
не требуется файл обученной модели.
